- **mtbc-bilan** [medium] : SKILL.md démesuré (127 KB / 2760 lignes, ~30k tokens à chaque chargement) : sortir le template de bilan (~lignes 1972-2606) et les recettes de génération TikZ/figures/Beamer (9.1ter, 9.4) vers references/ ou des scripts chargés à la demande, pour dégonfler le fichier et réduire la dilution d'attention. Le fond est bon, c'est un problème de forme/maintenabilité.
- **nextflow-development** [medium] : Internally inconsistent, likely-stale env check (verifiable from the file itself): Step 1 green-lights Java 11 (`apt install openjdk-11-jdk`, flags only `< 11`) yet also instructs `nextflow self-update`, which pulls the latest Nextflow — recent Nextflow releases have raised the Java floor above 11, so self-update + Java 11 can fail with an unsupported-class-version error. Recommend raising the Java requirement and re-checking the current floor against nextflow.io/docs/install, and re-checking whether the pinned pipeline versions (rnaseq 3.22.2 / sarek 3.7.1 / atacseq 2.1.2) are still current on nf-co.re, updating any that have fallen behind.
- **pangenome-enrichment** [medium] : L'entrée core (gene_presence.csv, strain×gene 0/1) est requise mais son origine n'est jamais expliquée : ajouter comment la construire (Panaroo/PPanGGOLiN pour le pangénome fermé MTBC) et clarifier que la pseudogénisation dérivée de TBannotator (frameshift/stop) ≠ absence de gène — sinon core/shell/cloud mélange deux notions.
- **pectinated-subclade-mining** [medium] : La commande de l'Étape 2 pointe vers un chemin périmé (`~/docs/codes/claude_plugins/bio/skills/pectinated-subclade-mining/scripts/find_synapomorphisms.py`) alors que le script réel est sous `bio_pathogens/skills/…` — le copier-coller échoue (No such file). Corriger le chemin (ou le rendre relatif au dossier du skill).
- **pysam** [medium] : Skill générique (chr1, comptage par gène type RNA-seq) non adapté au travail du groupe : remplacer les exemples par la référence MTBC mono-contig NC_000962.3 (pas de préfixe 'chr') et ajouter un exemple pileup/variant-calling à une position de résistance (ex. rpoB, katG) branché sur le flux SPDI ; préciser aussi que fetch()/pileup() sont 0-based half-open plutôt que la note floue '0-based/1-based selon contexte'.
